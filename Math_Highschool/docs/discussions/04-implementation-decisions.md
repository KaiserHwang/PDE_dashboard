# 기획 합의와 수직 구현 결정

Claude의 조건부 ACCEPT(03)를 받아 구현합니다. 실제 ES 모듈과 docs/authoring-contract.md를 사용하며 파일 형식/필드 명칭은 구현에 맞추되 학습 증거와 과제의 의미는 유지합니다.

- 핵심 경로: 대수18 + 미적분Ⅰ20 + 확률과 통계17, 선수 브리지10. 최종 실제 수는 콘텐츠 검증에서 산출합니다. 레슨 수는 출제 비중을 뜻하지 않습니다.
- 원순열을 필수 경로에서 제외, 상용로그와 모비율 추정/정규근사는 원문 확인 후 포함.
- 두 수직 레슨(C11 도함수 부호·극값, P8 조건부확률)과 브리지 B5/B7/B9를 먼저 작성합니다. 도함수 예제에서 Claude가 스스로 정정한 x=0의 도함수 최대도 반영합니다.
- 핵심 레슨: 선수2, 예측, 유도/이유, 조건·반례, 적합한 표현, 단계 예제, 빈 단계 채우기1, 기본2·전이2·오류 위치/이유/고친 답3·결함 설명 판정1(8개), 설명 체크리스트, 매개변수 변형 복습2개.
- 오류 분석은 연속된 위치·이유·수정 문항으로 구현합니다. 세 문항이 모두 맞아야 확인됩니다. 구간/집합/유리수 답 형식과 부분별 오류 피드백을 지원합니다.
- 최초 응답/도움 사용/교정 답변은 저장에서 분리합니다. 숫자만 바꾼 문제를 전이 과제로 세지 않습니다.
- 1/3/7은 로컬 달력 날짜 간격. 지연 확인은 별도로 실제 날짜 경과와 서로 다른 변형 성공을 확인합니다. 복습 실패/도움은 다음날 단계1. 3연속 실패는 이틀 뒤와 브리지 제안. 초기 증거 없는 학생도 복습에 포함.
- 정확한 유리수 채점(BigInt), 구간 경계/집합 순서에 대한 의미 비교。수치 근사는 문항이 허용한 경우에만.
- 공식 성취기준 코드는 직접 내려받은 최종 HWP의 코드와 절 제목으로 연결합니다. 원문 변환 쪽수를 확보하면 추가하고, 확보하지 못한 쪽수는 만들지 않습니다.
- 기획 논의/수정/검증 한계는 앱 '설계 기록'에서 읽을 수 있게 반영. 실제 교사·학생 검증이 없다는 문구를 표시합니다.

논의 중 Claude가 사용한 '공학적 검증이 유일한 방법' 같은 일반적 단정은 사실 보증으로 채택하지 않습니다. 리뷰는 내용·구현 검토이며 학습 효과 실증이 아닙니다.
